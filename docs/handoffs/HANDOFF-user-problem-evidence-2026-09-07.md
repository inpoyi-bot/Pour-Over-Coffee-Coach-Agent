## 7. Scope｜范围

### In scope

- 公开第一人称手冲 / V60 经历：获取配方、执行、表达味道、决定下一步、记录与复现。
- 替代行为：固定配方、视频、纸笔或表格、免费记录 App、社区求助、烘焙商建议，以及不使用工具。
- 继续、放弃、更换工具的具体经历；正面、负面、现有方案足够的反例。
- 与证据相关的竞品市场信息：定价及免费边界、可核验采用规模与口径、公开反馈覆盖和缺口。
- 与 v04 H1–H4、v03 已定义场景的对应关系；没有对应场景时提出候选，不能静默修改走查。

### Out of scope

- 执行原生 App 走查；此任务不依赖用户先交录屏。
- 烘焙商渠道全面扫描、试点差距审计、成本建模，分别属于 C/D/E。
- 用户招募、访谈、联系商家、购买或订阅。

### Explicit non-goals

不证明 AI 必要，不估算全球需求发生率，不给首发国家排名，不锁定价格或开发路线，不改代码、SPEC、eval 或提交材料。

## 8. Constraints and guardrails｜约束与研究规则

**检索与抽样**

1. 同时使用品牌词和用户任务语言。先读 v01/v02 的已有原始来源，再独立搜索“换豆调不好”“不想记参数”“固定配方够用”等场景；不能只搜支持产品的抱怨。
2. 优先执行日期前 12 个月；较早但相关的案例可保留，明确发布日期与适用版本。英语为起点，适当补充可访问的其他语言原始来源；报告地域与语言覆盖缺口，不能因“全球扫描”声称代表全球。
3. 自述使用者原帖、后续回复、商店文字评论为核心。开发者推广、官方案例、媒体或联盟营销另列，不能计入独立消费者经历。
4. 先取 5 条去重事件作为校准样本，尽量覆盖不同任务及反例；找不到反例就报告检索结果，不编造、不凑数。

**每条证据字段**

| 字段组 | 必填内容 |
| --- | --- |
| 溯源 | E-ID、直接 URL、来源类型、发布日期、检索日期、语言、页面读取程度（全文/摘要/不可访问） |
| 用户背景 | 自述经验、器材、地区；未说明一律“未知”，不从语言或商店区域推断 |
| 经历 | 触发情境、具体任务、问题、尝试的替代方案、结果、继续/切换/放弃行为 |
| 代价 | 时间、耗豆、金钱或求助投入，只填原文明示信息 |
| 可核验内容 | 短摘录或忠实释义；翻译明确标注；保留足够语境支持解释 |
| 质量 | 是否自述使用、关联推广风险、独立性是否可确认、去重依据、来源与选择偏差 |
| 分析 | 事实与解释分列；支持/反例/不明确；H1–H4 映射；v03 场景映射或“暂无对应” |

公开自述并不等于已经独立核实的真实效果。无法打开的链接列为线索；只有搜索摘要时标明限制，不补写情节，也不计入完整经历样本。同一用户同一事件、转载和商店重复展示合并；报告去重数量和来源分布。不得将样本中某问题的占比当作市场发生率。

**市场信息与隐私**

每次产出保留“市场背景与用户反馈”栏目。涉及竞品时核查可获得的价格、币种、地区、免费边界及规模口径；缺失写未知。第一轮无需扩大为市场规模研究，可简洁引用带原日期的旧基线并区分本轮新核验部分。不要用标价推断付费意愿，不用评分数推断留存，不把历史抱怨当当前版本缺陷。避免无关身份、联系方式与敏感个人信息；遵守网页访问和引用限制，不绕过登录或付费墙。

**写入归属**

只新增 `docs/research/user-problem-evidence-vNN-YYYY-MM-DD.md` 系列，每轮保留上一版。当前对话保留 `competitive-analysis-vNN-*` 的整合职责。不要覆盖旧研究、走查协议或本交接；不自动提交 Git。其他对话更新了研究文件时以最新文件为准，并记录读取版本。
