## 1. 建议：从资料扫描转到一次小范围的机会验证

**优先验证“新豆调校时，有人愿意持续使用并付费的决策帮助”是否成立。** 暂不启动完整商业 App，也不以补齐竞品全部功能为目标。用一次约两周的验证，回答三个按顺序相互依赖的问题：

1. **问题是否重要**：用户最近一次新豆调校，具体浪费了什么，现有方法为什么不够？
2. **解决方案是否有增量价值**：相对成熟引导/记录工具，我们是否降低负担，或更可靠地得到可复现的满意杯？
3. **谁会付钱**：消费者为一包豆的帮助付费，还是烘焙商为售后/复购结果付费？

推荐首个招募细分：已有 V60 和可调磨豆机、会基本冲煮，但每次换豆仍靠猜的人。这比“所有咖啡新手”更接近当前单轴能力；是商业验证的候选人群，不修改 capstone 用户定义。

两周从测试设备、参与者和可用流程准备就绪起算；招募不足则顺延，不为了日期把桌面分析写成用户结果。首发国家暂不锁定，先记录测试样本的语言、地区、设备与渠道，避免把方便招到的人误当成全球市场。

## 3. 功能拆分方法：按任务分层，不用勾选数决定胜负

功能有三个不同问题：是否提供、使用成本多高、能否改善结果。以下矩阵只回答前一个问题并标注限制，不能直接当体验分数或产品排名。

| 用户阶段 | 一级能力 | 二级功能 | 需要衡量的价值 |
| --- | --- | --- | --- |
| 开新豆 | 降低准备成本 | 扫袋/导入、豆袋建档、设备与水信息、未知信息处理 | 从拿起豆袋到得到可执行起点的时间与纠错次数 |
| 冲第一杯 | 降低执行难度 | 起点配方、比例/粉量、分步计时、设备数据采集 | 用户能否执行，实际操作是否偏离建议 |
| 喝完反馈 | 降低表达负担 | 味觉评价、实际参数、与上杯比较、说不清时的补问 | 完成率、耗时、误解与强迫猜测 |
| 决定下一杯 | 降低试错成本 | 使用历史、选择变量、控制步长、处理反常、停止或转介 | 建议是否可执行、是否根据证据更新、是否避免无效重复 |
| 找到满意杯 | 保留成果 | 找回/复现、豆级轨迹、备份、同豆新袋、跨豆偏好 | 是否愿意重复，下一杯能否复现，换袋后是否继续用 |
| 商业分发 | 降低获客及服务成本 | 商家配方后台、品牌指南、动态 QR、商品接入、效果统计 | 客户是否采用，支持时间/复购是否改善，付费能否覆盖成本 |

**图例：**“声明”=官方资料描述，不等于实测通过；“未核实”=当前证据不足，不等于没有；“本地”=本项目代码或记录支持；“演示”=本地演示能力，不等于可直接向消费者交付。

## 7. 功能投入建议：哪些验证、哪些延后

以下是商业化阶段的候选优先级，不是当前提交范围的变更。

| 优先级 | 能力 / 方向 | 推荐动作 | 进入开发的条件 |
| --- | --- | --- | --- |
| P0 | 从建档到满意配方复现的完整流程 | 先观察真实用户完成任务，定位断点 | 已有具体失败任务和可观察的改善目标 |
| P0 | 反馈负担 | 测最小有效反馈和按需补问；保留未知入口 | 更轻的表达没有损失必要诊断信号；不擅自删 guardrail |
| P0 | 反常、执行偏差与停止 | 与竞品对照；记录我方 E11/E13 已知限制 | 能稳定支持拟对外承诺的场景，且不把脚本通过当味道改善 |
| P1 | 扫袋、QR 或预填 | 先验证录入是否真是主要障碍；试点可人工预填并标记成本 | 能显著减少关键任务负担，收益超过配置/纠错成本 |
| P1 | 烘焙商品牌起点及支持流程 | 访谈/人工试点，暂不建完整后台 | 商家愿意提供配方、问题基线和明确试点承诺 |
| P2 | 硬件连接、社交、咖啡馆地图、全器材覆盖 | 暂缓 | 有明确目标人群需求，且核心价值已得到支持 |
| P2 | 跨豆推荐/消费市场平台 | 暂缓 | 已观察到跨袋复用或购买决策需求与可持续获客 |

不采用机械 RICE 总分：目前 reach、impact、confidence 缺可靠输入，数字化会制造假精确。先按能否改变投资决策排序。

| 准备期 | PM 确定招募条件、测试设备/版本；研究人员补齐测试材料 | 参与者筛选表、同豆同设备输入、证据记录表 | 是否有条件开展真实任务测试 |
| 第 1–3 天 | 研究人员走查 Cupsight、Pourist、Filtru；Beanconqueror 作免费记录参照 | 用 v01 T1–T6 留存输入/输出、字段、时间、付费墙 | 选出一个最相关直接竞品和一个简单替代方案 |
| 第 3–5 天 | PM 访谈 6–8 位目标用户；商家方向可另访 3–4 家烘焙商 | 近期真实经历、现有替代、成本和不愿切换的理由 | 是持续调校问题、单次配方问题，还是没有强问题 |
| 第 6–12 天 | 对愿意继续的人做同一包豆的短期使用观察 | 实际参数、建议、反馈、后续复现和退出记录 | 更好的建议是否产生可见收益，记录负担是否可接受 |
| 第 13–14 天 | PM 汇总证据并决定下一笔投入 | 一页继续/修改/暂停建议、证据及反例 | 是否做商业 MVP；暂不凭这轮宣布 PMF |

两周研究旨在降低早期风险，不能证明长期留存、复购提升或全球市场规模。小样本宜按个案呈现分子/分母，不包装成具有统计代表性的百分比。

每位参与者不需要测试所有产品。可用性阶段每人最多两个流程并平衡顺序；真实冲煮阶段尽量保持轨迹独立，避免学会第一款后让第二款占便宜。先取得熟悉效应和波动的观察，再设计较大样本的风味对照。

如果先用人工代办后台的方式验证服务，需要标清人工介入、耗时与成本。它只能验证服务价值；无人工介入的 Agent 可靠性必须独立评估，不得合并报告。

### 8.2 三道投资判断

| 判断 | 支持继续的证据 | 应收缩或暂停的证据 |
| --- | --- | --- |
| 问题是否值得解决 | 用户能讲出近期反复发生的具体困扰，并已有试错/求助行为 | 只在看完概念后说有兴趣；基础配方已足够 |
| 产品是否值得切换 | 用户独立完成后续反馈，找到并复现满意配方，能说出相对替代方案的具体收益 | 需要研究者持续提醒；操作负担超过收益；满意后不愿再用 |
| 商业模式是否成立 | 消费者在真实报价下付费，或商家承诺有明确资源与指标的试点 | 只有免费试用意愿；商家没有可量化问题或没有承担成本的人 |

这些是建议的决策框架，具体数值阈值需在执行前由 PM 确定。本报告没有擅自设定产品验收 gate。下一包豆复用与商家复购效果需要跨出两周继续观察。

### 8.3 可直接用于访谈的问题

消费者先谈过去的行为，再展示产品：

1. 最近一次开新豆，第一杯怎么决定参数？最后用了什么方法？
2. 哪一杯让你觉得需要调整？接下来实际改了什么，花了几次？
3. 有没有问烘焙商、看视频、用 App 或记笔记？为什么继续/放弃？
4. 如果明天要复现最好的一杯，能否现在找出具体参数？
5. 展示流程后，让用户独立完成任务并选择是否继续使用；将口头喜欢与实际行为分别记录。

烘焙商先查问题和付款人：

1. 最近一个月收到哪些具体冲煮问题，能否看去标识的实际例子？
2. 目前谁回答，每次多久？已有配方卡/二维码为什么还不够？
3. 客户冲不好是否影响退货、评价或复购？有哪些数据支持？
4. 若试点，会提供什么配方/客户触点/基线？谁决定预算？

本轮未发送招募、访谈或销售消息，也未购买订阅。当前工具不能完成原生 iPhone 操作；实机步骤需要具备可操作测试设备的人承担。此前浏览器超时不影响本轮公开资料和文档分析，但不补足实机证据。

## 9. 推荐定位与路线选择

候选定位：**为有基本器材但调校不稳定的手冲者，在每次换豆时提供容易执行的下一步，直到找到愿意重复的配方。** 此句是待验证价值主张，不是已经实现的效果承诺。

优先验证消费者价值，商家问题访谈可同时准备。先不把 B2C 订阅或 B2B2C 任一模式定死：若用户只需要偶发帮助，按包/单次服务可能比订阅更匹配；若商家确有高频支持问题且愿意承担成本，再推进渠道试点。价格应结合用户节省的成本、竞品免费边界及实际报价测试，不照搬市场均价。

**当前最小下一步：选 Cupsight / Pourist 中一个与 Filtru 做同任务走查，并对目标用户的最近一次开豆经历做问题访谈。** 先找出一个值得改善的具体断点，再决定商业 MVP；本轮已经补齐供此决策使用的桌面功能矩阵。
