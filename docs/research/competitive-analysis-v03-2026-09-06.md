> 前版：[v02 功能矩阵与商业化建议](competitive-analysis-v02-2026-09-06.md)；[v01 证据基线](competitive-analysis-v01-2026-09-06.md)。旧版保留。
> 本轮产出：目标、统一场景、操作脚本、指标与记录模板。状态为待执行，所有结果留空。
> 首轮对象：Cupsight → Pourist。先各走一次主流程，再做条件允许的分支。
> 测试性质：由 PM 执行的探索性功能走查，使用模拟味觉反馈。不是新手样本的可用性研究，不是实际风味验证，也不估计付费率或留存。

## 1. 本次要回答的五个问题

**总目标：找出从“开一包豆”到“拿到下一步并保存满意配方”的流程断点，决定后续真实用户测试优先验证什么。**

| 目标 | 具体问题 | 能支持的产品判断 |
| --- | --- | --- |
| G1 起点可执行 | 建档后，用户能否知道用多少粉、水、什么研磨，以及怎么开始？ | 是否需要优先解决建档、设备表达或冲煮引导 |
| G2 反馈可表达 | 能否表达变好、变差、说不清，而不用强行编造感官判断？ | 反馈设计有哪些必要信息和多余负担 |
| G3 建议可理解 | 下一步改什么、为什么，是否与可见反馈/实际操作一致？ | 候选价值在配方、引导，还是逐杯决策 |
| G4 成果可复用 | 满意后能否保留配方，退出再回来仍找得到？ | 满意停止和配方复现应如何定义 |
| G5 免费路径可到达 | 哪一步要求登录、付费、额外数据或设备？ | 首次价值出现前的使用门槛是什么 |

不在本轮下结论：建议的科学正确率、喝起来是否更好、真正使用了何种模型/记忆、真实长期留存、商业 PMF。输出提到“上杯”只能证明可见解释，不能证明内部实现。

本协议对接 [SPEC §3](../SPEC.md) 的起点、反馈、更新与停止，以及 D4 的建议/执行区别。竞品可调整水温、比例等；不以我方研磨单轴范围要求竞品。

## 2. 你需要准备什么

你负责操作、录屏并说出卡住的地方；我负责事后计时、拆字段、比较配方、编码证据和更新 MD。无需边操作边填完整研究表。

1. 一部可运行两款 App 的设备；记录机型、系统、App 版本、商店地区、界面语言和测试顺序。
2. 同一包真实咖啡豆的标签照片，以及同一套设备资料。照片用于测试识别，不需要实际冲煮。只需在下面的“资料卡”填一次。
3. 从进入 App 前开始录屏。登录/验证码/付款信息不录入交付素材；必要时暂停，恢复后说出场景编号。
4. 测试内容保持私有，允许时标记为 TEST/模拟。若无法避免模拟评价公开发布，停在提交前，记录该限制。
5. 优先使用已有免费入口。付费墙截图并记录价格、币种、周期、试用/续费条件和出现步骤；本轮不要求购买或启动自动续费试用。

建议分两次完成：主流程每款预留约 20–30 分钟，分支每款另留约 15–25 分钟；这是排期估计，未验证 App 的实际耗时。若计时器不能跳过，按真实界面等待并记录。

### 一次性资料卡

| 项目 | 统一值 / 填写规则 |
| --- | --- |
| 用户任务 | 我会基本 V60 冲煮，但换豆后不知道如何调整，想找到下次愿意照做的配方 |
| 咖啡 | 同一真实豆袋；名称、产地、处理法、烘焙度按标签填写，未写就选未知/留空 |
| 标签图片 | 两款使用同一张清晰照片；是否支持从相册导入也记录 |
| 烘焙日期 | 同一真实日期；不知道就未知；尽量同一天测试，避免豆龄差异 |
| 滤杯 | Hario V60；型号/尺寸照实际填写，两款保持一致 |
| 磨豆机 | 同一真实型号、刻度单位和当前设置；不确定不猜。任一 App 不支持时记录，不能静默替换 |
| 粉量需求 | 15 g；若产品不允许，记录其默认量和偏离，继续观察可到达流程 |
| 水/滤纸 | 两款填写同一信息，未知就未知；不为凑字段编造矿物质数据 |
| 偏好 | 一开始只表达“平衡、不要明显酸苦”；不先替 App 作欠萃/过萃诊断 |
| 其他设备 | 记录相同条件；首轮不连接蓝牙秤，单独记录连接是否为必需 |

“统一”指用户、豆、设备、需求和反馈语义统一，不强求两款生成相同配方。每款自己的起点分别记为 R0；后续建议依次为 R1、R2。每个杯子同时记录“计划配方”和“模拟实际执行值”。

若 App 强制填写资料卡里没有的信息，先找未知/跳过；没有则记录必填阻碍。为了继续而采用默认值时，记录该默认的来源，相关结果标为条件不完全一致。

## 3. 执行规则：保证可比，又不过度折腾

- **先自然找入口，再求助。** 单个入口找约 2 分钟仍无进展，就说“此处没找到”，保留画面；之后可看 App 帮助，另记一次求助。2 分钟是本次查找预算，不是行业易用性标准。
- **不猜按钮名称。** 以下脚本描述操作意图，按实际界面找对应功能，入口差异本身就是证据。
- **先读懂量表。** “感受到多酸”和“想要更多酸”不是一件事。保留字段标题、端点、默认值，按场景语义填，不能机械选同一数字。
- **评分锚点统一，原始值保留。** 初杯=明显不满意；改善=较满意但仍想改善；满意=愿意复现；变差=比初杯更不满意。如果支持 0–10 可用 4/7/9/2。不同尺度选最接近的语义档位并记录，不假装转换后完全相等。
- **未知不等于中等。** 不确定场景中无评分就不补评分；强制评分且无“说不清”入口时，记录表达受阻，不擅自填 5 分。
- **模拟反馈明确标记。** 所有杯子均为功能测试输入。跳过计时/模拟结束不算真实冲煮，也不能解释为已验证执行效果。
- **保留第一次输出。** 不因不满意而反复生成后挑最好的一条。网络失败最多重试一次并保留两次状态；额外重复运行另编号。

## 4. 主流程：第一次只做 S1–S5

流程：资料卡 → S1 起点 R0 → S2 模拟初杯 C1 / 建议 R1 → S3 改善杯 C2 / 建议 R2 → S4 满意杯 C3 → S5 退出后找回。

### S1｜新豆建档并获得起点

**目标：** G1、G5。起始状态：尚未建立本次测试豆袋。

操作：

1. 进入 App，按首次用户路径开始；如需登录，记录出现位置。
2. 用资料卡建立一包豆。优先尝试扫描/相册输入；不可用则记录并转手动。
3. 对照原标签检查识别结果；错误先截图，再修改。资料未出现在标签上但被自动填入，也标记来源未核实。
4. 设置 V60、磨豆机和 15 g 需求，生成或取得第一份配方 R0。
5. 展开完整配方，尝试找到开始引导/计时的入口；不需要实际冲煮。

**完成证据：** 豆袋详情、器材配置、R0 完整参数与操作步骤、可用的下一步入口。保留识别错误及付费墙。

**观察：** 必填项、修改次数、未知入口、设备缺失、首次得到可执行配方的总耗时；参数表达是否可落实到该磨豆机。

### S2｜记录一杯不满意的咖啡，取得下一步

**目标：** G2、G3。前提：已有 R0。

模拟事实卡 C1：

> 我按 R0 冲了第一杯。明显偏酸、偏薄，甜感弱，不满意。没有上一杯可比较。没有观察到的床面、流速等信息保持未知。

操作：

1. 进入记录/完成冲煮路径，模拟实际值按 R0；若有强制计时，记录跳过或等待方式。
2. 按界面量表表达 C1。不要主动输入“这是欠萃、请磨细”。
3. 如有追问，只按事实卡回答；没有信息则回答不知道。
4. 提交后打开下一步建议 R1，展开完整内容，再打开历史确认 C1 是否保存。

**完成证据：** 提交前的反馈表、提交后的 C1 历史和 R1。若只有记录没有建议，记录“仅记录”，不把任务结果补写成自动教练。

**观察：** 反馈表达是否完整；是否要求比较一杯不存在的前杯；R1 改什么、为什么；计划参数与实际值是否分开。

**这里是分支基线 B。** 保存 C1 的完整输入、R0、R1 及时间。后面的异常场景均尝试回到这一逻辑状态，不在满意杯之后继续叠加异常反馈。

### S3｜建议后变好，但还想改善

**目标：** G2、G3。前提：基线 B。

模拟事实卡 C2：

> 这次我按 R1 做了。比第一杯更好：酸感减弱，有一点甜感，但还想改善。目前较满意。没有新增的客观测量。

操作：记录 R1 为模拟实际值 → 输入 C2 → 回答必要追问 → 保存 → 查看 R2 和历史。

**完成证据：** C2 的输入、R2、两杯历史。记录界面能否直接表达“比第一杯更好”。

**观察：** 是否提到具体历史；是否保持、修改或缩小调整；解释是否与 C2 相容。改动多或少都先描述，不预设只有继续磨细才算正确。

### S4｜我满意了，想保留这杯

**目标：** G4。前提：S3 后的 R2；若没有新建议，则使用 App 明确让用户继续的配方并记录。

模拟事实卡 C3：

> 我按刚才的方案做了。这杯满意，我希望下一杯原样复现，不想再继续调整。

操作：记录 C3 → 明确表达满意和复现意图（若界面允许）→ 查看默认下一步 → 保存/收藏/选择重复此配方（若有）。

**完成证据：** 满意反馈、默认下一步、实际保存的配方。记录是否能表达“满意”之外的“希望不再改变”。

**观察：** 默认继续改配方、保留原配方还是提供可选探索？“无需继续调整”的体验不一定需要出现“收敛”一词。默认复现与可选探索可以并存，不能因有探索入口就判失败。

### S5｜退出后回来，找到满意配方

**目标：** G4。前提：已保存 S4 的满意杯。

操作：

1. 离开 App 并正常关闭后重开，不卸载、不清除数据。
2. 从首页找到同一包豆和满意杯，打开完整配方。
3. 找到可复用/再次冲煮的入口，停在确认前即可，不再制造新反馈。
4. 对照 S4：豆、器材、粉水、研磨、温度和步骤是否保留。

**完成证据：** 重开后的导航过程、找到的配方与 S4 对照。

**观察：** 找回耗时/步骤、是否误入其他杯、配方是否默默变化。这只检查一次关闭重开，不证明跨设备同步或长期持久性。

## 5. 分支测试：主流程后再做

### 如何复刻基线 B

优先用产品提供的独立测试记录/复制入口：同一资料卡 → R0 → C1 → R1。不要假设删除记录会清除模型或用户级记忆；不删除已有个人记录、不创建多账号规避额度。

如需新建测试豆袋，复制资料并记录新袋 ID。若它被自动合并、继承旧反馈、或重新生成的 R1 与原来不同，标为“基线不完全一致”。可以做探索性观察，但不能声称严格控制变量或把输出差异归因于单一反馈。

没有可独立复刻的方式、额度不足或被付费墙阻挡时，分支留为未执行；不要把几种互相矛盾的情况连续灌进同一条历史。各 App 内的分支优先保持同基线；跨 App 的 R0/R1 可以不同。

### B1｜调整后明显变差

**前提：** 独立基线 B。模拟事实：按 R1 做，较 C1 明显变差；苦味明显、余味不悦，很不满意，未获得新的客观测量。

操作：输入该反馈 → 记录追问 → 查看下一步 → 与 R0/R1 对照。

观察：是否承认变差、说明依据、保留可回退的配方、修改或暂停建议。记录其是否反向/回退，但不强制要求一定反向；追问、检查实际执行也可能合理。不能从模拟苦味判定科学上的过萃。

### B2｜我说不清有没有变差

**前提：** 另一个独立基线 B。模拟事实：按 R1 做，似乎有一点苦，但不确定，也说不清整体比 C1 好还是差；没有可靠的新测量。

操作：找“不确定/跳过/备注”路径 → 只填已知信息 → 如能提交则查看回应；不能表达时保留表单。

观察：能否不打明确分数；是否强迫确定方向；回应是澄清、保守建议还是确定诊断。强制填中间分才可继续时，先记“无法按原语义提交”；若为探索而填，另标失真输入，其输出不计入本场景结果。

### B3｜建议值与我实际做的不一样

**前提：** 另一个独立基线 B。模拟事实：R1 已给出，但这杯忘了调整，实际仍完全使用 R0；口感与 C1 相近。

操作：在记录入口尝试填写 R0 为实际值 → 表达未执行新方案 → 提交 → 检查历史和下一步。

观察：能否区分计划 R1 与实际 R0；是否误称“刚才这次调整没有效果”。若 R1 本来等于 R0，本分支不适用，应记 N/A，不能另编一次变化。若 UI 不支持实际参数，也记录其是否可用备注表达及系统是否承认。

### 只在出现异常时补做的核查

若一个结果将支撑“竞品有严重问题”这一判断，在相同条件可复刻时再验证一次并保留全部输出；无法复刻则写“单次观察”。第二次生成不用于替换第一次。两次同样也不证明统计可靠性。

## 6. 统一观察指标与结果编码

### 6.1 指标定义

| 指标 | 如何记录 | 使用边界 |
| --- | --- | --- |
| 场景结果 | 完成 / 部分完成 / 未完成 / 被阻挡 / 未执行 / 不适用，附原因 | 未找到入口不等于产品不支持；付费限制不等于算法失败 |
| 总任务时间（秒） | 从本场景首个动作到取得完成证据/停止；标记录屏时间戳 | 下载、登录验证、解说暂停另记；任务内等待需保留 |
| 操作与等待时间 | 总时间拆为实际操作、系统等待、强制计时；另标解说/外部中断 | 首次探索与已学会的重复动作不能混为平均值 |
| 输入负担 | 必填字段数、实际填写数、被迫猜测数、重复录入数 | 从录屏回看统计，不要求操作者边用边数 |
| 导航负担 | 点击/选择、返回、求助次数；一段连续打字算一次输入动作 | 不把输入 30 个字算 30 次点击；仅作同任务参考 |
| 识别质量 | 标签可核验字段、识别正确项、漏项、错误项、无来源自动填项 | 未印在标签上不等于错误；单袋不报告通用准确率 |
| 反馈保真 | 完整表达 / 部分表达 / 无法表达；保留字段标签与选项 | 强度、偏好方向与满意度分开看；空值不是中等 |
| 配方变化 | 前后粉量、水量/比例、研磨、温度、步骤及时间逐项差异 | 按“调整意图”计变量；固定比例下粉水联动不是两个独立决策 |
| 建议清晰度 | 分别记录是否说清改什么、具体到什么程度、依据是什么 | 解释清晰不等于解释正确；无调整时看是否说明保持/追问 |
| 历史与实际值一致性 | 对照已保存输入，记录引用正确、错误或未提及 | 未提及历史不等于内部没用记忆；提及也不证明真正推理 |
| 满意成果可复用 | 是否可定位满意杯、保存参数、重开后原样找回 | 一次成功不等于持续留存或长期备份可靠性 |
| 商业门槛 | 登录/权限/付费出现阶段，价格币种周期、试用和额度 | 页面报价不是付费意愿；不因不同商店币种直接排名价格 |

不汇总成“智能度 85 分”或竞品总分。用每个任务的证据、负担与阻碍作比较。

### 6.2 结果代码与影响

- **完成**：达到场景规定的可观察终点。
- **部分完成**：例如记录保存但没拿到下一步，或保存了满意杯却无法方便找回。
- **未完成**：实际操作后没达成；注明是输入限制、流程问题、搜索预算内未找到还是其他。
- **被阻挡**：登录、付费、网络、权限、不可保持私有、基线不可复制等阻止有效观察；下游不记零分。
- **未执行**：尚未做；**不适用**：场景前提不存在，例如 B3 没有实际配方变化。

影响按场景描述：阻断关键任务 / 可绕过但增加负担 / 轻微不便。不用一次个人体验推算用户群发生率。

## 7. 录屏与记录模板

## 9. 走查后如何形成下一步判断

1. 把功能状态从“官方声明/未核实”更新为“在指定版本、地区、订阅层的一次观察”，保留截图和原文。
2. 按 G1–G5 整理最重要的断点、产品各自有效的做法以及仍不可判断的地方。
3. 每条机会写成“具体用户任务 → 观察障碍 → 候选改进 → 需验证收益”，不直接变成扩功能清单。
4. 严重负面判断优先复核；每条结论同时列其他解释，例如学习效应、基线不同、权限或付费限制。
5. 选择最多两个问题进入真实用户测试，再决定是否投入实现。用户真实反馈负担、真实味道与支付需要后续单独验证。
